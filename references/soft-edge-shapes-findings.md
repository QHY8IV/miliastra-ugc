## TL;DR（先看这五条）

1. **软边光斑"当底"只在低频图划算**：平滑渐变图同 MAE **省 12–24%**；高频细节图**倒亏 16–49%**；混合图 **≈0**；真实插画（6k 控件）**省 ~9%**。
2. **软边"形状"（不当底，让形状选择器自己挑）永远不亏**：同 MAE 省 **1.4%（10.6k 控件）→ 2.6%（6.7k）→ 6.2%（5k）**。**预算越紧越值钱。**
3. **剂量极陡**：羽化 `f=0.10` 赚 9%，`f=0.50` **亏 18%**。羽化必须薄——薄羽化≈不透明（所以不亏），但保住了"边缘那圈像素用一个控件盖掉"的能力；厚羽化失去不透明芯（120px 光斑在 ±40px 外就失效）。**最优点尚未定位**（只测了 0.10 与 0.50）。
4. **两者叠加会互相吃掉**：软底单独 +9%、软形状单独 +2.6%，同时开只剩 **+4.7%**。**选一个，别都上。**
5. **落盘链路没通**：`kind 5` 进不了关卡（4 处断点，见文末）。

## 机制解释（为什么是"低频赢、高频亏"）

软边基函数（`shapes-core.mjs:80-86`）：

```
α(x,y) = smoothstep(2x/L) · smoothstep(2y/L)     L = 0.83 × 宽度参数（真机 29 号校准）
```

- **低频区**：一个软边控件编码的是"一段连续斜坡"，`控件数 ∝ (Δ/L)²` 的面片分割在平滑处本来就低效，软边直接跨过去。
- **高频区**：同样这段斜坡会**抹掉本应保留的边缘**——误差不降反升，同时还要为羽化付额外控件。
- **预算维度**：软边的优势要在"画质已经逼近、只剩边缘误差"时才兑现。C 图在 150 控件量级（MAE ~1.8）远没到那个精度，所以是 0；R2 在 6k 量级才吃到 9%。**同一张图、不同预算，结论会变。**

## 复现

```
（作者本机目录，未随技能分发）
  run-ABC-softbase.ps1     三阶段：造光斑集 → 六路并行 → 汇总
  force-soft.mjs           把任意光斑集强制成全软（自检：已知样本 fx/r 应为 0.1）
  joint.mjs                联合评估（纯矩形/形状/仅光斑/光斑+形状/同控件数）
  ab.mjs                   单臂 A/B
  result.json              基函数实验（soft vs opaque 作为纯基函数）
  joint_*.log, spot-soft-exp.log
```

调用要点：

```
# 1) 造两臂光斑集（同一组位置，只改 kind）
node spot-fit.mjs R2_360x203.rgb 360 203 30 --out sw_opaque.json
node force-soft.mjs sw_opaque.json sw_allsf10.json --f 0.10

# 2) 联合评估（--T 与 --T2 两档，用于同 MAE 插值）
node joint.mjs R2_360x203.rgb 360 203 sw_allsf10.json --T 4.5 --T2 5.5 --lib <rect-merge>
```

`T` 的语义（实测）：**T 变大 → 控件变少、MAE 变差**，它是"接受门槛"不是"目标 MAE"。**别把 T 当质量旋钮。**

## 两条裁决性未知（只有真机能验，优先级最高）

1. **两只不同色软边叠 50% 重叠，中间是平滑过渡还是硬切/渐隐到父色？**
   28/29 号只校准了单只羽化 profile（L≈0.82–0.83×宽度），**重叠零证据**。整个"软边重叠省控件"建立在 alpha-over 真会混合这个假设上。
2. **`SetSoftEdgeWidth` 每个控件的加载开销**。已测 `SetLocalRotation` 约 10 ms/次，软边**可能更贵**——若贵一个量级，上面所有收益都会被吃掉。

## 待办（按性价比）

1. **羽化剂量扫描** `f = 0.05 / 0.10 / 0.20 / 0.30`（A 与 R2，约 20 分钟）——最优点还没定位。
2. **打通落盘四处** + 跑 `check.mjs`，产出可用 `.gil`。
3. **选择器**：开软边 ⟺ 图像高频能量占比低于阈值 **且** 目标预算足以逼近画质。A 类（天空/光晕/雾/暗角/大面柔和渐变）开；B 类（线稿/像素画/高频纹理）关。

## 局限（写死的，别忽视）

- 只有 **4 张图**（3 合成 + 1 真实插画），绝对值不能当普适常数。
- **C 图的斜率只跨 10 个控件**（150→140），那个 0.4% 在噪声里，无统计意义。
- 全部为**模拟层**（JS 合成），真机叠放语义与性能开销均未验证。
- 早期"软底 6/6 图省 2.4–19.5%"的结论走的是 `--spotted` 旧路径（每图 8 个色块起点），与本文 `--seed-shapes` 路径**同 T 不可比**，已作废。
