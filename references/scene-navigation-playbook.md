# 场景与寻路排障

适用：怪物不走桥、卡在平台边缘、追击或巡逻异常，以及通过工具生成或修改 GIL 场景。

## 先区分三项证据

| 检查层 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 几何与碰撞 | 地板和桥是否同高、相接、有碰撞；尺寸与原点换算是否正确 | 桥面已进入导航网格 |
| 编辑器导航烘焙 | 当前场景已经执行导航生成；可进一步查看烘焙结果 | 所有怪物、目标和路线都能正常运行 |
| 试玩 | 指定兵种在指定路线实际过桥并继续攻击 | 未测试兵种和其他路线也正常 |

GIL/GIA 编译、容器回读、引用匹配和节点模拟通过属于离线检查，不能替代导航烘焙或游戏寻路实测。

## 官方依据与必要步骤

- **【文档：mhn9vpia00qc】** “关卡设置 → 地形导航”说明：修改地形或静态物件摆放后，应重新烘焙寻路网格体。需要造物寻路时，发布前核对该页面的寻路网格上传开关。
- **【文档：mh6c3uri84h2】** 导航网格定义可行走区域；寻路阻挡标记造物不可行走区域。物件有碰撞不等于其表面已被导航覆盖。
- **【文档：mhnffmieeqbg、mhlh4n9m4i56】** 静态物件用于布景，不支持添加通用组件或节点图；玩法需要动态控制的塔、机关等应保持动态类型。

## GIL 生成器容易丢失静态标记

**【实测：2026-10-01 王冠奇域项目，原生种子对照及离线回读】** 改名函数将整个名称属性替换成 `{'1': name}`，丢掉原生积木的静态标记。两块地板、两座桥、四面围墙因此被导出成动态单位。用户试玩截图显示怪物在桥边停滞。

在本次 Ayaya 工具解析结构中：

```text
GIL root['5']['1'][实体记录]['5']
  property['1'] == 1
  property['11']['1'] = 名称
  property['11']['2'] = 1  # 原生静态标记
```

依据是原生 `template_instance_exemplars.gil` 中积木记录的名称属性，以及 `qrcode_entity/block_assembler.py` 使用 `NameProperty.StaticBlock.STATIC = 1`。这是**具体解析器与原生样本的逆向核对**，不是官方通用字段定义。换实体类型、工具或格式版本时重新对照，不能套用未经核实的字段号。

修改名称时只改名称子字段，保留同一属性内的其他元数据。场景积木不要为改名重建整个名称属性。

本次修正恢复八个场景物件的静态标记，去除其无用途的自定义变量；保留四座塔和 AI 国王的动态类型、战斗属性、显示配置和节点图。不要把需动态控制的物件一起转成静态。原生静态存档仍可能携带序列化基础属性或空默认数据，不能以“不支持组件”为理由盲目删除全部序列化组件。

**【未确认】** 本次已验证静态标记错误及修正后数据；尚未收到重新烘焙后怪物成功过桥的游戏回传。因此没有证明该错误是停滞的唯一原因，也没有证明所有动态物件都不能用于寻路。

## 排查顺序

1. **核对加载文件。** 区分导出文件、编辑器当前加载内容、烘焙后保存内容。需要比较时请求当前实际保存的 GIL。
2. **核对场景类型。** 地板、桥等布景是否按设计为静态；名称元数据是否被生成器清掉；静态场景是否误挂节点图或自定义变量。
3. **核对模型、碰撞和接缝。** 使用已测量的原生模型尺寸与原点，检查桥两端与平台顶面连接。不能默认模型单位尺寸为 1 米，也不能默认原点在体积中心。
4. **执行导航烘焙。** 若未完成或最后一次烘焙早于场景修改，先重新烘焙并保存；需要发布时核对上传开关。
5. **试玩一条完整路线。** 用地面近战兵种测试出生 → 接近桥 → 过桥 → 到达目标 → 攻击，再测另一方向和另一座桥。记录兵种、阵营、路线、停滞位置及烘焙后的文件。
6. **仍失败才展开逻辑排查。** 查看实际导航连接、寻路阻挡、造物行为模式、入战/脱战设置和仇恨目标。仇恨只表明目标选择，不能证明路径可达。不要直接把受限于造物状态图的移动战术当作普通服务端节点，或未验证就用运动器/瞬移替代原生走桥。

## 导出前的有效检查

- 最终 GIL 的场景类型与清单一致；静态布景无玩法图挂载，塔和 AI 国王保留动态逻辑。
- 改名只改名称；与原生种子核对相关元数据。修改前后对照实际记录，检查没有顺带改变碰撞、可见性、位置和缩放。
- 桥面与两岸同高且相接；分别使用游戏测试结果确认路径，而不是只看包围盒。
- 报告明确记录 `navigation_baked`、`native_crossing_test` 的实际状态。没有运行游戏就写未执行，不把离线检查升级成实机确认。

本次证据文件：项目的 `导出/寻路修正核对.json`、两份 `*_离线检查.json`、修正前 GIL 与 `build_level.py`。离线核对通过的是两个版本各八个静态标记，以及未改变的桥面几何、碰撞和玩法实体；不包含游戏导航生成结果。
