# 服务器节点图：图规格与生成

`scripts/gi.mjs graph build` 把**图规格**（JSON）编译成 `.gia`；`graph show` 把已有的图反编译回图规格。
这是本技能里"agent 直接写节点图"的入口——AGENTS.md 旧的"不能替你连线"在这里被改写为：
**能生成节点图资产文件，由用户走官方资产导入；不能在编辑器里替你点。**

范围：**服务器侧**的 实体 / 状态 / 职业 / 道具 节点图。客户端图（技能、过滤器）只读。

## 1. 图规格

```jsonc
{
  "name": "示例—进入触发器后加分并销毁",     // 图名（编辑器里看到的名字）
  "kind": "entity",                          // entity(默认) | status | class | item
  "vars": [                                  // 节点图变量（可选）
    { "name": "次数", "type": "Int", "value": 0, "public": false }
  ],
  "nodes": [
    { "id": "e",   "node": "进入碰撞触发器时", "pos": [0, 0],     "then": "set" },
    { "id": "get", "node": "获取自定义变量", "T": "Int", "pos": [0, 220],
      "in": { "目标实体": { "from": "e.进入者实体" }, "变量名": "积分" } },
    { "id": "add", "node": "加法运算", "T": "Int", "pos": [320, 220],
      "in": { "a": { "from": "get.变量值" }, "b": 1 } },
    { "id": "set", "node": "设置自定义变量", "T": "Int", "pos": [640, 0],
      "in": { "目标实体": { "from": "e.进入者实体" }, "变量名": "积分",
              "变量值": { "from": "add.结果" }, "是否触发事件": false },
      "then": "del" },
    { "id": "del", "node": "销毁实体", "pos": [960, 0], "in": { "目标实体": { "from": "e.触发器实体" } } }
  ]
}
```

`node scripts/gi.mjs graph example` 会打印这份示例；它是自检的一部分，保证能编译。
（它只是**接线示范**，不保证玩法语义——比如自定义变量该挂在哪个实体上要按你的玩法定。）

### 节点字段

| 字段 | 必填 | 含义 |
|---|---|---|
| `id` | ✓ | 稿内标识，任意唯一字符串。形如 `n12` 时会被当作节点序号 12 保留下来（反编译出的规格靠这个保住原序号） |
| `node` | ✓ | 节点：**中文名**（与官方节点文档一致）/ 英文名 / 标识符 / 数字 ID。`gi.mjs nodes find <关键字>` 查 |
| `T` |泛型时✓| 泛型绑定。单参数写 `"Int"`；双参数写 `{"K":"Str","V":"Int"}`。可选值 `gi.mjs nodes show <节点>` 会列出 |
| `pos` | | `[x, y]` 画布坐标，缺省 `[0,0]`（全叠在一起也能用，只是难看；请自己排开） |
| `in` | | 数据入引脚 → 常量或连线，见下 |
| `then` | | 执行流：连到哪个节点，见下 |
| `comment` | | 节点备注文字 |
| `idx` | | 显式指定节点序号（一般不用） |
| `raw` | | 反编译时不认识的节点原样保留在这里；见 §6。**不要手写** |

### 引脚怎么称呼

在 `in`、`then`、`from` 里，引脚可以写：**中文名**（节点文档里的参数名）、英文标识符、或 1 起的序号。
先按名字匹配，匹配不到且形如数字才当序号（有的节点引脚名字就叫 "0"、"1"，如「拼装列表」）。
同名时优先可见的引脚。`gi.mjs nodes show <节点>` 列出全部引脚。

### 常量（`in` 里写值）

| 引脚类型 | 写法 | 例 |
|---|---|---|
| 整数 `Int` | 整数 | `1` |
| 浮点 `Flt` | 数字 | `0.5` |
| 布尔 `Bol` | `true` / `false` | `false` |
| 字符串 `Str` | 字符串 | `"积分"` |
| 三维向量 `Vec` | `[x, y, z]` | `[0, 1.2, 0]` |
| GUID / 元件 / 配置 / 阵营 `Gid Pfb Cfg Fct` | 整数 ID | `30001009` |
| 枚举 `E<…>` | **英文名**或数字 | `"Ascending"`、`600`（`nodes show` 列出可选值；报错时也会列） |
| 列表 `L<…>` | 数组（元素同上，仅基础类型） | `[1, 2, 3]` |
| 实体 `Ety` | **不能写常量**，只能连线 | — |

泛型引脚（`R<T>`）的类型由 `T` 决定：`T:"Int"` 时 `b: 1` 是整数；`T:"Flt"` 时是浮点。

### 连线

- **数据**：`"in": { "入引脚": { "from": "节点id.出引脚" } }`；省略 `.出引脚` 取该节点第一个可见的数据出引脚。
- **执行流**：`"then": "目标id"`（连第一个执行流出引脚，目标的第一个执行流入引脚）；
  多个出口按引脚名：`"then": { "是": "a", "否": "b.流程入" }`；一个出口连多个目标写数组。
- 事件节点（"当…时"、"…触发时"）**没有执行流入引脚**，不能当 `then` 的目标；「获取…」「…运算」这类纯数据节点没有执行流，只靠数据连线参与计算。

### 节点图变量 `vars`

`{ "name", "type", "value?", "public?" }`，`type` 取 `Int Flt Bol Str Vec Ety Gid Cfg Pfb Fct` 或它们的列表 `L<Int>`… ；实体类型不能设初值。
用「获取/设置节点图变量」节点时，变量名写成 `变量名` 常量；名字没在 `vars` 里声明会给 warn。

## 2. 命令

```sh
node scripts/gi.mjs nodes find 自定义变量            # 查节点
node scripts/gi.mjs nodes show 设置自定义变量        # 全部引脚、泛型变体、枚举可选值
node scripts/gi.mjs graph build 规格.json -o 图.gia  # 可以给多个规格 → 一个组合 .gia
node scripts/gi.mjs verify 图.gia
node scripts/gi.mjs graph show 图.gia                # 反编译回规格
node scripts/gi.mjs graph put x.gil 规格.json -o x.new.gil   # 直接放进关卡（逆向推断，见 README §4C）
```

报错示例（真实输出，都会指明位置和可选项）：

```
nodes[0](a)：找不到服务器节点 "计时器"；你是不是想找：暂停全局计时器(309)、获取全局计时器当前时间(310)、启动全局计时器(311)、…
nodes[1](b).in.目标实体：类型不匹配：入引脚需要 Ety，来源出引脚是 Int
nodes[0](c)："设置自定义变量" 是泛型节点，需要用 "T" 指定类型（例如 "T": "Int"）；可用的 T：{"T":"Int"} {"T":"Str"} {"T":"Ety"} …
nodes[0](e).then：节点 "进入碰撞触发器时" 没有执行流入引脚 "(默认)"（它可能是事件节点，事件节点不能作为执行流目标）
nodes[0](a).in.目标：节点 "销毁实体" 没有数据入引脚 "目标"（可用：目标实体）
nodes[0](a).in.目标实体：实体类型的引脚不能写常量，请用连线
nodes[0](a)："节点图开始" 是客户端节点（客户端技能/过滤器图用的），本工具只生成服务器节点图
```

## 3. 生成的编码规则

【官方示例】来自对样本里 169 张节点图（其中 139 张服务器图）的分析；每条都被样本印证：

- 每个节点：`shell_ref`（外壳，泛型用基类 ID）+ `kernel_ref`（内核，泛型用具体变体的 `KernelID`），
  身份都是 `{ SYSTEM_DEFINED(10001), <图类别>, SYS_CALL_STUB(22000), runtime_id }`。
- 引脚只写"有用的"：**输入执行流引脚不写**；输出执行流引脚**有连线才写**；数据入引脚**有连线或被设置过才写**；
  **泛型（`R<T>`）的入/出引脚总要写类型占位**（游戏据此确定具体类型）。
- **连线记在哪一端**：数据连线记在**入引脚**上（指向来源的出引脚）；执行流连线记在**出引脚**上（指向目标的入引脚）。
- 节点内引脚按 `(种类, 序号)` 升序；`shell_sig` 是界面上的序号，`kernel_sig` 是执行时的序号，个别节点两者不同——用节点表 + `kernelFix`，不要手写。
- `chosen_type_index`（泛型引脚的类型选择器序号）来自变体的 `InjectedContents.TypeSelectorIndex`；序号 0 不写。
- 有些节点固定带一个 `context_declaration`：「结算关卡」(77)、「设置玩家结算成功状态」(652)，样本里 18 处逐字节相同，本工具自动补上。
- `TypedValue` 里 `type_def` / `is_value_set` 的有无：官方导出里**并不统一**（整数常量就有 7 种形态），说明游戏读取这一层是宽容的；本工具取每种类型的多数派。
  逐节点对照官方编码：85.9% 完全相同，其余差异全是这类形态差异。

## 4. 节点表

`references/formats/data/nodes.json`（由 `scripts/build-node-table.mjs` 生成）：558 个节点（服务器 434 / 客户端 124）、94 个枚举类型、274 个枚举项。

- 来源【第三方】：社区节点表（MIT，`schema/THIRD_PARTY_LICENSES.md`），**game 6.2.0**。作者用"导入游戏再导出"的碰撞法实测节点 ID。
- 与官方样本核对：样本里 131 种系统节点 ID，122 种在表里（93%）；缺的 9 种是 7.x 新增的节点与"造物状态决策"类。
  样本里服务器节点的 6091 个引脚（种类+序号）**全部**在表里，2008 个带类型的引脚类型码**全部**吻合。
- `kernelFix`：表与样本在 5 个节点（挂载循环特效、播放限时特效、创建元件、唤起卡牌选择器、创建投射物）的 18 个引脚上 kernel 序号不同，**以样本为准**，加载时自动应用。
- 枚举项只有英文名（表里没有中文枚举名）；节点/引脚的中文名来自游戏的本地化文本。

**表里没有的节点怎么办**：不要猜 ID。让用户在编辑器里拖一个该节点，导出成 `.gia`，用 `gi.mjs graph show` 读——那个节点会以 `raw` 出现，可以透传，也能拿来核对引脚。

## 5. 校验（GG1xx 规则）

`gi.mjs verify` / `check-gia-gil.mjs` 对每张图检查：节点序号重复(GG101)、连线指向不存在的节点(GG102)、节点 ID 不在表里(GG103, warn)、
引脚不存在(GG104)、数据连线两端类型不匹配(GG105)、连线方向/种类不对(GG106)、泛型 kernel 不在变体里(GG107, warn)、图 GUID 重复(GG109)、服务器/客户端节点混用(GG113, warn)。
官方样本上 **0 个 error**。

## 6. 反编译与 raw

`graph show` 输出的规格里，凡本工具不认识/不覆盖的节点变成 `{ "id": "n7", "raw": { …原样… } }`：

- 节点表里没有的（7.x 新节点）、信号节点、带备注坐标的、值里带 schema 没有的字段的（如界面布局类节点）。
- **透传**：`graph build` 把 raw 节点原样写回；别的节点可以用 `"then": "n7"` 连到它，用 `{ "from": "n7.<数字出引脚序号>" }` 取它的数据。
- 图级内容（含字典/结构体的变量、图注释、复合节点端口映射、入口序号）放在 `spec.extra`，同样原样透传。
- 反编译会在 stderr 打印说明（哪些节点为什么走 raw），别忽略它。

## 7. 支持范围一览

| | 支持 | 备注 |
|---|---|---|
| 服务器 实体/状态/职业/道具 图 | ✓ 新建、反编译、修改 | 状态/职业的身份常量为【第三方】，未被样本印证 |
| 固定节点、泛型节点（T） | ✓ | |
| 基础类型常量、枚举、基础列表 | ✓ | |
| 执行流、数据连线 | ✓ | |
| 节点图变量（基础类型） | ✓ | 字典/结构体类型透传 |
| 备注文字 | ✓ | 不含带坐标的独立注释 |
| 信号（发送/监听）、复合节点、结构体节点 | ✗ 不能新建 | 反编译时 raw 透传 |
| 字典、结构体类型的引脚 | ✗ | 报「暂不支持」 |
| 客户端图（技能、过滤器） | ✗ 只读 | |
| 节点图与实体的挂接 | ✗ | 用户在编辑器里挂 |
