# .gia / .gil 直写手册

> 本技能的第 5 个域：**直接读、写千星奇域的存档文件**——`.gil`（关卡存档）与 `.gia`（资产导出包）。
> 入口工具 `scripts/gi.mjs`，检查器 `scripts/check-gia-gil.mjs`。规则见 `AGENTS.md`「规则四」。

## 0. 一分钟版

| 你要做的 | 怎么做 | 证据 |
|---|---|---|
| 看一个存档里有什么 | `node scripts/gi.mjs info x.gil` | 【官方示例】 |
| 把 Lua 放进/更新到关卡 | `gi.mjs lua put` → `gi.mjs lua check` | 替换已有脚本：【官方示例】字节级往返；新增脚本：【逆向推断】 |
| 查 Lua 里的控件名是否真在存档里 | `gi.mjs lua check x.gil` | 【官方示例】 |
| 生成一张服务器节点图（.gia） | 写图规格 → `gi.mjs graph build` | 结构与编码：【官方示例】；节点 ID：【第三方】+样本核对 |
| 改用户已有的节点图 | `gi.mjs graph show` → 改规格 → `graph build` / `graph put` | 同上 |
| 弄清一个新字段落在哪 | 编辑器里改一个设置、各导出一份，`gi.mjs diff A B` | — |
| 任意存档 ⇄ JSON | `gi.mjs json` / `gi.mjs build` | 【官方示例】50/50 字节级往返 |

**这套工具没有在真机上导入验证过。** 所有产物在交付时必须带上"未在真机验证 + 导入检验步骤"（见 §6）。

## 1. 文件是什么

| | `.gil` | `.gia` |
|---|---|---|
| 是什么 | 一整个关卡的存档（我的奇遇 → 导出存档）【文档】`mhjuwpiubrh0` | 一个或多个资产的导出包（元件/技能/状态/节点图…）【文档】`mhxbd59urbfu` |
| 怎么进游戏 | 存档页面 → 导入存档 | 系统菜单 → 资产导入导出工具 → 加载外部资产 |
| 内容 | 地形、实体、界面控件、节点图、脚本…… | 选中的资产 + 它们依赖的关联资产 |
| 引用怎么处理 | 关卡内自洽 | 导入时 GUID 被**重新分配并保持相互引用**【文档】`mhxbd59urbfu`「引用关系恢复」 |

另有协作模式的 `.gilh`（核心文件）+ 64 个 `.gis`（切片）【文档】`mhj3gr0ye4wg`——本工具**不处理**。

两者外层容器相同（§2），载荷都是 protobuf。协议细节见 `container.md`、`gia.md`、`gil.md`。

## 2. 容器（20 字节头 + 载荷 + 4 字节尾，大端）

## 4. 工作流

### A0. 只想核对 Lua 里的控件名（最省事，只读）

日常迭代 Lua 走的是本机 `external_lua_file\*.lua`（改完重新试玩，见 `references/lua-ui-playbook.md`），**不需要**改存档。
让用户 **我的奇遇 → 导出存档** 一份，然后：

```sh
node scripts/gi.mjs ui 关卡.gil                                   # 看控件树与绑定
node scripts/gi.mjs lua check 关卡.gil --name 脚本名 --file main.lua   # 核对磁盘上的脚本
```

这只**读**存档，不会改它，也不涉及"真机导入"的风险。
想顺便**离线整局跑一遍**（用存档里的控件树与布局）：`node scripts/sim-lua.mjs smoke 脚本.lua --gil 关卡.gil`（不给 `.lua` 就用存档里嵌着的脚本），见 `lua-sim.md`。

### A. 把 Lua 放进关卡（要产出可分发的关卡存档时）

1. 让用户在编辑器里 **我的奇遇 → 导出存档**，得到 `x.gil`。**先备份。** 关卡里要先有一个客户端脚本资产和它所属的控件（脚本要绑在控件上才会跑）。
2. `node scripts/gi.mjs lua ls x.gil` 看现有脚本；`node scripts/gi.mjs ui x.gil` 看控件树。
3. 写 / 改 Lua，先过 `node scripts/check-lua-ui.mjs 脚本.lua`（Lua 侧规则）。
4. `node scripts/gi.mjs lua put x.gil --file 脚本.lua --name <脚本名> -o x.new.gil`
5. `node scripts/gi.mjs lua check x.new.gil`：按 Lua 里的 `GetChild/FindChild` 逐层核对控件树，**名字对不上会精确指到行和层**。
6. `node scripts/gi.mjs verify x.new.gil`，再按 §6 导入验证。

替换脚本只动 `client_scripts.scripts[i].source` 一个字段，其余字节原样保留【官方示例】：把脚本原样写回，文件与原文件**字节相同**。
**新增**脚本（`lua put --new`）需要同时在分类页签里登记，样本里只有一个脚本，多脚本形态无法核对，属于【逆向推断】；控件与脚本的**绑定**目前只能在编辑器里做。
注意：官方脚本是 CRLF 换行；Lua 不受影响，但要 diff 时先统一换行。

### B. 生成节点图（.gia）

1. 明确图的种类：`entity`（实体图）/`status`（状态图）/`class`（职业图）/`item`（道具图）。客户端图（技能、过滤器）本工具不生成。
2. **节点名不要凭记忆写**：`node scripts/gi.mjs nodes find <关键字>`、`nodes show <名字|ID>` 查节点、引脚（中文名）、泛型的 T 取值。节点表里没有的就是没有——**不要编 ID**，让用户导出一份含该节点的 `.gia`，再用 `graph show` 读它（未知节点会以 `raw` 原样保留并透传）。
3. 按 `node-graph.md` 写图规格（JSON）。`node scripts/gi.mjs graph example` 有可编译的示例。
4. `node scripts/gi.mjs graph build 规格.json -o 图.gia`：报错会指明哪个节点、哪个引脚、可用的有哪些。
5. `node scripts/gi.mjs verify 图.gia`。
6. 交给用户走官方资产导入（§6），在节点图管理器里把图挂到实体上。

### C. 修改已有的图

`gi.mjs graph show x.gil --name <图名> > 图.json` → 改规格 → `gi.mjs graph build 图.json -o 图.gia`（推荐，走官方导入）或 `gi.mjs graph put x.gil 图.json -o x.new.gil`（直接写进关卡，【逆向推断】）。
反编译里认不出的节点会变成 `{"id":"n7","raw":{…}}` 原样保留，其他节点照常改，连线用 `"n7.数字引脚序号"` 指向它。

### D. 逆向一个新字段

在编辑器里只改一个设置，前后各导出一份存档，`node scripts/gi.mjs diff 前.gil 后.gil`，输出按路径列出新增/删除/修改。把发现记进 `references/formats/gil.md`，并注明证据等级。

## 5. 不做什么（边界）

- **不从零新建 `.gil`。** 关卡里有太多没解析的板块（地形、实体、关卡设置……）。要新关卡，让用户在编辑器里建一个再导出，工具在它上面增改。
- 不处理 `.gilh/.gis/.gip/.gir`。
- 节点图：客户端图（技能/过滤器）、字典与结构体类型的引脚、信号节点、复合节点、图注释——**读得到、改不了**：反编译时以 raw 保留，编译时透传，但不能新建。
- 元件、实体、地形、关卡设置等板块：可 `info/dump/json/diff` 查看和整体 JSON 编辑，没有高层 API。
- 不覆盖原文件：写命令必须给 `-o`；目标已存在要 `--force`，并自动留 `.bak`。

## 6. 导入检验流程（必须交给用户做，交付时写明）

因为我们没有真机，**每个产物第一次用之前**都要走一遍：

1. **备份**当前存档（存档页面 → 导出存档）。
2. 在**一个测试关卡**里试，不要直接在正式关卡上导入。
3. `.gia`：系统菜单 → **资产导入导出工具** → 把 `.gia` 放进本地资产目录 → **加载外部资产**。
   注意【文档】`mhxbd59urbfu`：*每次本地资产导入会清空并刷新千星沙箱内所有资产库页签的内容*，想留的资产先**转存**。
   `.gil`：存档页面 → **导入存档**。
4. 打开节点图管理器 / 脚本 / 控件，逐项确认：节点数量、连线、常量、脚本内容、控件名字。
5. 试玩触发一次。
6. **回报**：成功就在 `verification-ledger.md` 对应行记一笔（日期、编辑器版本）；失败请给出 `gi.mjs verify` 的输出 + 让编辑器把出问题的资产重新导出一份，
   `gi.mjs diff 我们生成的.gia 编辑器导出的.gia` 就能看出差在哪一个字段，据此修正本技能。

## 7. 常见坑

- **节点被游戏悄悄删掉**：基类 ID 错了游戏会直接删节点；泛型的具体 ID 错了会被置空【第三方】。所以泛型节点务必写对 `T`，工具会据此选 kernel。
- **kernel 序号**：引脚有 shell 序号（界面上第几个）和 kernel 序号（执行时第几个），个别节点两者不同。工具用节点表 + 样本校正，**不要手写**。
- **GUID**：`.gia` 里的 GUID 只需自洽，导入时游戏重分配【文档】；往 `.gil` 里放东西则必须与已有 GUID 不冲突（工具会挑未占用的）。
- **7.x 新节点**：节点表是 game 6.2.0 的，样本里 9 种节点不在表里。遇到就走 raw，不要猜。
- **控件同名**：`GetChild(名)` 只取第一个同名子控件，同名会让脚本行为不可预测。
- **换行**：官方脚本是 CRLF；用 `sed` 在 Windows 的 Git Bash 里处理可能悄悄改成 LF，不影响运行但会让 diff 变噪。
- **JSON 里的大整数**：超过 2^53 的 64 位整数在 JSON 里是十进制字符串，写回时接受字符串。
