# .gil（关卡存档）

官方【文档】`mhjuwpiubrh0`《1.4存档导入与导出》：存档页面（游戏内 派蒙菜单 → 我的奇遇；或编辑器内 ESC 菜单）→ 导出存档得到 `.gil`，导入存档读回。

## 1. 顶层板块

载荷是一个大 protobuf 消息。下表「文件数」是 48 个官方 `.gil` 样本里出现该字段的个数（【官方示例】）；
「含义」列：【官方示例】= 本技能核对过并有 schema；【第三方】= 只采用了 script-1024 文档里的命名，本技能**没有**解析其内部。

| 字段 | 文件数 | 含义 | 证据 | 本技能 |
|--:|--:|---|---|---|
| 2 | 25 | 关卡名 `level_name` | 官方示例 | 可读可改 |
| 3 | 48 | 恒为空消息 | 官方示例 | 保留 |
| 4 | 48 | 元件 / 玩家·角色模板（`{items[]}`，每项 `f1` 是模板 GUID） | 第三方 | 不透明 |
| 5 | 48 | 关卡内布设的实体（体量最大） | 第三方 | 不透明 |
| 6 | 48 | **分类页签**（每类资产一棵页签树，默认页签「未分类页签」） | 官方示例 | 有 schema |
| 7 | 48 | 地形 | 第三方 | 不透明 |
| 8 | 48 | 「似乎也是元件数据」 | 第三方 | 不透明 |
| 9 | 48 | **界面控件**（控件节点树） | 官方示例 | 有 schema，见 `lua-and-ui.md` |
| 10 | 48 | **节点图相关**：图、复合节点/信号/结构体接口、信号表、结构体定义 | 官方示例 | 图有 schema |

| 23,25,27,29 | 34 | 外围系统（计分/成就/排行榜）、装饰物、编辑器信息等 | 第三方 | 不透明 |

| 1 / 52 / 53 | 1 | 仅最新（7.1.0）文件有：GUID 与时间戳形的数，含义未确认 | 官方示例 | 保留 |

### 版本差异

样本的编辑器版本：42 个**没有**字段 43（早期格式），3 个 6.2.54，2 个 6.7.0，1 个 7.1.0。
格式随版本演进——新版本多出字段（客户端脚本 50、字段 1/52/53……）。**不要跨版本"补字段"**：往旧格式的存档里塞新版本才有的板块，游戏是否接受没有依据。
本工具对没有客户端脚本板块的存档拒绝 `lua put --new`。

## 2. 已核对的板块

### 分类页签（字段 6）【官方示例】

```
categories.trees[]  { category_kind, root{name:"root",kind:1}, default_tab{name:"未分类页签",kind:2, assets[]{asset_kind, asset_guid}} }
```
每类资产一棵树；资产 GUID 登记在页签的 `assets` 里。客户端脚本这一类：`category_kind = 69`，`asset_kind = 7900`。

### 界面控件（字段 9）【官方示例】

```
ui.roots[]                 (501, 打包) 顶层布局 GUID
ui.nodes[]                 (502) 控件节点 UiNode
  guid (501) · info[] (502) · children[] (503, 打包, 顺序=兄弟顺序) · parent (504) · slots[] (505)
```
数据槽 `(slot_id, slot_type)` 的组合决定它存什么；名字槽是 `(2,15)`，`name.text` 就是 Lua `GetChild` 用的名字。
详见 `lua-and-ui.md`。

### 节点图（字段 10）【官方示例】

```
node_graphs.graphs[]      (1)  每张图一条，形态 = NodeGraphContainer.InnerWrapper { graph }（同 gia.md 的 NodeGraph）
node_graphs.interfaces[]  (2)  复合节点 / 信号 / 结构体节点的接口（≈ NodeInterface），不透明
node_graphs.folders       (3)  { f1:数, f2:{f1:"复合节点"} } 一类文件夹名
node_graphs.signals       (5)  信号表，不透明
node_graphs.structs[]     (6)  结构体定义，不透明
```
图与实体的**挂接**信息不在这里（在实体记录里，本技能未解析）；`graph put` 因此只写图本体，需要用户在编辑器里挂接。

### 客户端脚本（字段 50）【官方示例】

```
client_scripts.scripts[]  (1)  { guid(1), name(2 资产名), file_name(3 如 main.lua), source(5 Lua 源码明文) }
client_scripts.field_2    (2)  样本里恒为 1
```
脚本被两处引用：分类页签（上）与控件的脚本绑定槽（`lua-and-ui.md`）。

## 3. 怎么在不认识的板块里找东西

```sh
node scripts/gi.mjs dump x.gil --path entities --depth 3      # 看实体板块前 3 层
node scripts/gi.mjs dump x.gil --path '#15[0]' --depth 2      # 没在 gil.proto 里声明的板块用 #字段号
node scripts/gi.mjs diff 前.gil 后.gil                        # 改一个设置前后各导出，按路径看差异
node scripts/gi.mjs json x.gil --path level_settings -o 关卡设置.json   # 导出子树，改后 gi.mjs patch 写回
```

**路径怎么写**：`gil.proto` 里声明过名字的板块（哪怕内部不透明）用声明名——`components`(4)、`entities`(5)、`terrains`(7)、`field_8`(8)、`level_settings`(11)；
没声明的字段号用 `#N[0]`。声明为不透明的板块，内部内容在它的 `_u` 里，路径写 `entities.#1[0]`（该板块的第 1 个 `#1` 子消息）。

样本里读得懂的一些名字（说明第三方对这些板块的命名靠谱）：`entities` 的第一项是「关卡实体」，字段 15 的第一项是「背包模板」。
**这只是印证命名，不代表可以往里写**：这些板块本技能没有解析，改动前必须自己先用 `diff` 弄清楚字段含义。

发现新字段的含义后，把它记进本文件和 `schema/gil.proto`，并写明证据等级与来源样本。
