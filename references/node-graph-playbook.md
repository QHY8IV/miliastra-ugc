# 服务器节点图 · AI 写图作业说明

> 节点图是图形化编辑的，agent 不能在编辑器里替你连线——**但能产出可导入的节点图资产文件**。
> 语法、节点字段、编码规则在 `formats/node-graph.md`；**本文讲流程、边界、验收**，两份配合看。
> 工具：`scripts/gi.mjs graph build|show|put`、`nodes find|show`；检查器 `scripts/check-gia-gil.mjs`。

## 0. 这条路通不通：官方原文

【文档】`mho777i0ga90_千星沙箱.md`（服务器节点图管理器主要功能）：
**「可通过节点图外部资产进行服务器节点图的导入」**。

所以链路是：

```
AI 写规格 JSON → graph build → 图.gia → 用户在编辑器「资产导入导出 → 加载外部资产」→ 挂到实体上
```

**导入这一步没有真机验证过。** `formats/verification-ledger.md` 里 `graph build` 那一行的「真机导入」是**待验证**。
交付时按 AGENTS.md 规则四写清楚，别把「检查器 0 error」说成「能跑」。

## 1. 该写图还是该写脚本

| 要做的事 | 归谁 | 依据 |
|---|---|---|
| 权威状态、判定、结算、实体增删、计时 | **服务端节点图** | 客户端只有变量读接口，没有写接口 |
| 每个玩家自己的界面、输入、本地表现 | **客户端 Lua** | `lua-ui-playbook.md` |
| 两边通信 | 客户端 `ServerSignal` / `RegisterServerSignalHandler`；状态走自定义变量 | `api/client-ui-api.md` |

**口诀**：会影响别人、别人必须看到的东西 → 节点图；只影响自己那台机器的画面 → Lua。

## 2. 四步流程

### 第 1 步 写规格：先查节点，不要凭印象

```sh
node scripts/gi.mjs nodes find 自定义变量      # 中文名 / 英文名 / 数字 ID 都能搜
node scripts/gi.mjs nodes show 设置自定义变量   # 引脚名、泛型变体、枚举可选值
node scripts/gi.mjs graph example              # 一份可编译的完整规格
```

规格语法见 `formats/node-graph.md` §1。**每个节点名、每个引脚名都要在 `nodes show` 的输出里出现过**——写错会被工具挡下（这是这套工具比 Lua 好的地方：它不是静默的）。

### 第 2 步 编译，**读警告**

```sh
node scripts/gi.mjs graph build 规格.json -o 图.gia
```

输出三段，都要看：

| 段 | 含义 |
|---|---|
| `⚠ …` | 结构合法、但语义可能不对（**信号节点没有绑定**就在这一段） |
| `已写出 …` | 落盘成功，不代表对 |
| `复检：0 个 error` | 对生成物重新跑检查器，只证明结构自洽 |

### 第 3 步 回读：确认写进去的就是你以为的

```sh
node scripts/gi.mjs verify 图.gia        # GG1xx 规则：序号重复、连线悬空、引脚不存在、类型不匹配…
node scripts/gi.mjs graph show 图.gia    # 反编译回规格，逐条对照
```

**不动点**：`show → build → show` 两次规格必须完全一致（自检就是这么锁的）。
**不要拿文件哈希比**：`.gia` 头里带导出时间（Unix 秒），同一张图隔一秒重编哈希就不同——这不是错。要字节级比，用同一次 `build` 的输出。

### 第 4 步 交付给人导入

写清四件事：产物路径、`verify` 结论、**"未在真机验证"声明**、导入步骤与失败回报方式：

- 导入：编辑器 **资产导入导出 → 加载外部资产**，**先在测试关卡试**
- 失败回报：编辑器报错原文 / 能导入但节点标红 / 能导入但运行时不触发（三者原因完全不同）

## 3. 六条硬边界（都会让图"看着对、跑不动"）

| # | 边界 | 现象 | 怎么办 |
|---|---|---|---|
| 1 | **信号节点不能绑定信号** | `监听信号` / `发送信号` 编译通过、检查器 0 error，但游戏里永远不触发——工具不写 `signal_version`，`graph build` 只给一条 ⚠ | 导入后在编辑器里**手动选信号**；或从含该节点的导出物 raw 透传（§5） |
| 2 | 复合节点 / 结构体 / **字典引脚** | 工具报「暂不支持」 | 拆成基础类型；必须用就 raw 透传 |
| 3 | **客户端图**（技能 / 过滤器） | 只读 | 客户端逻辑走 Lua |
| 4 | **图与实体的挂接** | 工具不做 | 编辑器里挂。**挂错对象 = 图不跑**；「事件源实体」= 挂这张图的那个实体 |
| 5 | **节点表是社区逆向的 6.2.0** | 7.x 新节点查不到 | 让用户拖一个该节点、导出 `.gia`，`graph show` 读进来当 raw |
| 6 | **`.gia` 与 `.gil` 两条路** | `graph put` 是逆向推断 | 优先 `.gia` + 手动导入；`graph put` 只在用户明确要求、且接受「未验证」时用 |

补充两条不那么显眼、但会咬人的：

- **泛型节点必须给 `T`**（`设置自定义变量`、`减法运算`…），不给会直接报错；给了具体类型的变体，工具才能选对 kernel。
- **`vars` 里没声明的节点图变量**，工具只给 warn、照样编译——但游戏里读出来是 0。用 `获取/设置节点图变量` 前先把变量写进 `vars`。

## 4. 报错 → 改法（工具的真实文案）

| 报错 | 原因 | 改法 |
|---|---|---|
| `找不到服务器节点 "计时器"；你是不是想找：…` | 节点名不是正式名 | 用提示里的名字 |
| `节点 "X" 没有数据入引脚 "Y"（可用：…）` | 引脚名写错 / 该节点没有引脚 | 按「可用」列表改 |
| `"X" 是泛型节点，需要用 "T" 指定类型` | 漏了 `T` | 补 `"T": "Int"` 之类 |
| `实体类型的引脚不能写常量，请用连线` | 给 `Ety` 写了数字 | 从事件节点的出参连线 |
| `节点 "X" 没有执行流入引脚（它可能是事件节点…）` | 把「当…时」当成了执行流目标 | 事件节点只能作起点 |
| `…是客户端节点…本工具只生成服务器节点图` | 混用客户端节点 | 拆到 Lua |
| `信号节点「监听信号」没有信号绑定…` | 见边界 1 | 编辑器里手选信号 / raw 透传 |

## 5. 从导出物学节点（补节点表最可靠的方式）

表里没有的节点（7.x 新增、或表里漏的），**不要猜 ID**：

1. 让用户在编辑器里拖那个节点，随便连一下，导出成 `.gia`
2. `node scripts/gi.mjs graph show 导出.gia` —— 不认识的节点会以 `{ "id": "n7", "raw": { … } }` 出现
3. 把那段 `raw` 原样放进你的规格：`graph build` 会**逐字节写回**，别的节点还能用 `"then": "n7"` 连它、用 `{ "from": "n7.2" }` 取它的数据出引脚
4. 同时对照 `nodes show` 的引脚列表，确认你要接的引脚序号

**注意**：raw 带着**原图**的身份和绑定（包括信号引用、GUID 之类）。它适合「同一张图里改改」，**不适合跨图搬**——搬过去可能指向原图的信号，而那张图根本不在这个关卡里。

## 6. 验收清单

交付前逐条打勾：

- [ ] 每个节点名、引脚名都在 `nodes show` 的输出里出现过
- [ ] `graph build` 的 ⚠ **全部看过**（尤其信号节点那条）
- [ ] `verify` 0 error
- [ ] `show → build → show` 规格一致
- [ ] 节点图变量都写进了 `vars`（或用的是实体身上的自定义变量，并在交付说明里点名）
- [ ] 交付写明「未在真机导入验证」+ 导入步骤 + 失败回报方式
- [ ] 与客户端脚本对账：信号名、变量名、实体类型三处逐字一致（见 §7）

## 7. 联机场景的对账表（必做）

节点图和客户端脚本之间**只有字符串约定**，一个字不同就是静默失效：

| 约定 | 节点图侧 | 客户端侧 | 必须一致 |
|---|---|---|---|
| 信号名 | 「监听信号」绑定的那个信号 | `game.ServerSignal("Attack")` | ✓ |
| 变量名 | `设置/获取自定义变量` 的 `变量名` | `game.GetGlobalCustomVariableValue(…, "BossHp")` | ✓ |
| 实体类型 | 变量写在**哪个实体**上（关卡实体 / 玩家实体） | `Enum.CustomVariableEntityType.Level` / `PlayerSelf` | ✓ |
| 变量是否声明 | 该实体的**自定义变量组件**里有这条（不是节点里动态创建） | 客户端只能读到**组件里默认创建**的变量 | ✓ |

可跑的完整例子（客户端脚本 + 服务端图规格 + 双客户端回放）：工作区 `lua-mp-demo/`。

## 8. 不确定清单

写图这条路上，下面这些**不要当成事实**：

- **真机导入没验证过**（`graph build` / `graph put` 都是）。
- **信号节点的绑定字段编码未知**：`signal_version` 只在反编译侧见过，没写过。新建的信号节点能不能在编辑器里补选信号——**未确认**。
- **「事件源实体 = 挂载这张图的实体」**是社区口径（`bbs-faq*.md` 多处一致），不是官方节点文档。
- **7.x 新增节点不在表里**（558 个节点是 6.2.0 的），遇到就按 §5 补。
- 状态 / 职业节点图的身份常量是【第三方】，没被样本印证。
